Ashapp v0.0.3. Release publication requires successful Windows x64, macOS Intel and macOS Apple Silicon builds, with source archives, build manifests and SHA-256 checksums from the same commit. Local regression and protocol-core checks have been exercised; fresh VPS provisioning remains unverified.

VLESS + Reality + XTLS Vision can now be selected alongside kernel AmneziaWG in manual setup or templates. A dedicated, SHA-256-pinned sing-box 1.14.4 systemd service preserves protocol separation. Each device has its own UUID/Short ID, with create/rename/revoke and repeatable export. One immutable connection model generates a standard VLESS link, its exact QR payload, and standalone Xray/sing-box client JSON. The export dialog selects, copies or saves each format; no server private key or administrative data is exported.

Both Xray 26.10.31 and sing-box 1.14.4 clients passed real local HTTPS traffic through the production-generated sing-box server config. Independent QR decoding matched the URI. Revoking one test UUID stopped its traffic while another device kept access. Choosing sing-box as the server avoids the reproduced current Xray-server/sing-box-client Reality handshake incompatibility. This is local core interoperability, not verified Linux provisioning or simultaneous live AmneziaWG/VLESS traffic. VLESS changes briefly restart only its service; existing AmneziaWG behavior is preserved. See docs/VLESS.md for tested versions and limitations.

Ashapp v0.0.3 adds client management for existing official AmneziaVPN `amnezia-awg` and `amnezia-awg2` containers: create a client in a selected VPN installation, rename existing clients, revoke access, and reopen saved private configurations as files, clipboard text or QR codes. QR and copy actions reuse the existing key. The public key has a separate copy action. Host kernel clients can also be renamed. Every operation targets its original server, source and public key.

Original client .conf files can be imported into protected storage after key/server/PSK/address validation, without changing the peer. Imports are hidden by default and overwriting a saved copy requires an explicit choice. Executable hooks and stale configurations are rejected. A lost private key cannot be reconstructed from public peer data. Large QR payloads offer a copy/file fallback.

Client changes preserve both clientsTable formats, apply only the selected live peer without a VPN restart, check for concurrent edits and roll back ordinary failures. An uncertain rollback retains private recovery files and blocks further changes. Do not edit the same VPN in both apps concurrently. Existing private keys cannot be recovered from public peer data; old clients without their original private configuration can be renamed/revoked but not exported. Use AmneziaVPN for container service controls. Kernel setup still refuses to replace existing Docker deployments. Actual Docker/VPS interoperability remains unverified; mocks and Bash transaction tests are not a live-server test.

Ashapp configures an existing Ubuntu/Debian VPS over SSH, installs kernel-mode AmneziaWG and/or VLESS + Reality, manages per-device VPN clients and optionally installs authenticated SOCKS5.

Manual setup and reusable templates share one flow. Multiple servers, including different SSH ports on the same IP, retain independent sessions, credentials and management state. Protected answers use the operating system's secure storage.

README explains launch instructions, prerequisites and checksum/provenance verification.

Runtime testing on physical Apple Silicon is pending. This repository and its release downloads are public.
