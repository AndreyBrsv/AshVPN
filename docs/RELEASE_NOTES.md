Ashapp v0.0.7 adds configurable server security, SSH-key access and private SOCKS5 forwarding.

- Setup and templates share SSH protection, firewall, OS-update and password-login choices. Automatic security updates and disabling password SSH login are off by default. Legacy templates preserve their previous behavior.
- Manage > Security provides per-endpoint diagnostics, draft controls, read-only previews and address unbanning. Policy changes require confirmation through a new SSH connection before a 180-second deadline. Server timers and a boot recovery unit retain recovery independently of the app.
- Generate a unique SSH key or import a key/passphrase. Key-only migration requires independent login/sudo verification and protected OS-vault saving. Key text stays hidden; copying it is explicit. Administrator setup no longer implicitly reopens password authentication.
- Fail2ban protects actual SSH ports using a journal-backed jail: 5 failures in 10 minutes, 15-minute ban. Owned IPv4/IPv6 firewall rules preserve existing ports/policy and handle supported Docker publications. Unsupported external configurations require manual review. OS auto-updates permit only security origins without automatic reboot.
- Public SOCKS5 remains default. Private mode requires stable Docker Engine 28.0.0+ on the server, binds to server loopback and offers a local SSH tunnel in Manage. Older/unknown/prerelease daemons cannot create/start private proxies or issue supported private connection details. Existing unsupported private services remain stoppable or explicitly replaceable. Ashapp does not upgrade shared Docker automatically. Mode/credential replacement interrupts existing connections; tunnels close with their session.
- Progress shows current activity, completed steps and elapsed time. Endpoints retain independent state. App updates wait for server tasks, private tunnels and pending security confirmation.

Updating: from an installed v0.0.4 or newer, select Check for updates and complete the system installer after all work is idle. Complete native ZIPs, installers, source, manifests, checksums and public provenance are published from one source commit after all three native targets pass. Earlier release commits/tags/assets remain.

Validation limits: no fresh-VPS deployment, real Fail2ban packet filtering, forwarding or reboot recovery was exercised. Local tests replace privileged commands; the forwarding transport test uses loopback and a fake SSH channel. Dependency installation and completed setup steps can remain after later failure. Keep the hosting console available; see docs/SERVER_SECURITY.md. Actual installer/OS-vault retention, physical Apple Silicon and macOS sandbox flows require manual validation. Windows is unsigned; macOS uses ad-hoc signing without notarization. Checksums/provenance do not prove reproducible or defect-free builds.

The compact workspace, Carbon branding, appearance, protected client copy/QR, updater and independent kernel AmneziaWG/VLESS services are retained. No credentials, private keys, local profiles or security-review artifacts belong in release source.
